# GitHub 同步

GitHub **只同步配置**。同步和配置包导出共用 `src/main/configBundle/collect.ts` 的收集器，由 `common.ts` 的配置路径规则统一限定范围。配置来自 Electron userData：

- `settings.json` 的可移植设置：编辑器设置、快捷键、主题选择、字体设置、代码模板、补全片段，以及 `pluginEnabled`（插件 ID → 是否启用，未指定时启用）。模板和片段是设置中的字符串，不收集源文件。
- `themes/` 下的自定义主题及资源、`fonts/` 下的自定义字体。字体文件也随配置迁移。

不读取或遍历 `~/.iter` / `ITER_STORE`；题目配置、测试数据、代码快照、代码库和其他源文件均不参与同步。`plugins/` 的插件代码、清单和依赖，以及 `plugin-data/` 的运行数据也不参与同步；插件需在各设备分别安装。最近打开的文件和目录、登录令牌、同步记录、冲突备份、配置导入备份、临时/锁文件和符号链接不会上传。即使远端存在这些文件，也不会下载或删除它们。

配置文件超过 `sync.maxFileBytes` 时列入跳过结果，默认上限为 50 MB；另有配置文件 128 MiB、设置 JSON 1 MiB 的硬上限。跳过的文件不会被当作本地删除。

配置包也采用相同范围：新导出的 `iter-config` 格式版本为 **2**，不再打包插件代码。导入只替换设置、主题和字体，保留本机已安装的插件；`ImportSummary.plugins` 字段保留兼容，值为 `0`。旧版（版本 1、包含插件目录）的配置包仍可导入：通过路径、类型和大小校验后，仅恢复当前范围内的配置，忽略插件代码及其他已不属于配置的内容；再次导出时使用版本 2。

## 登录

- 浏览器登录：默认使用 ITER 内置的 GitHub OAuth App（公开 Client ID：`Ov23li0fKDLZXNdvHDVp`），已启用 Device Flow，无需自行注册应用。点击登录后，ITER 显示设备验证码并打开 GitHub，由用户在浏览器完成授权。无需提供 Client Secret 或密码；设备授权申请 `repo` scope。该应用签发的 OAuth 访问令牌不会自动过期，但可被撤销；设备验证码仍有独立有效期。高级设置中的非空 Client ID 可覆盖内置值，自建应用需启用 **Enable Device Flow**。
- 令牌登录：先在 GitHub 创建自己的私有同步仓库，勾选 **Add a README** 初始化，再到 **Settings → Developer settings → Personal access tokens → Fine-grained tokens** 创建令牌，选择 **Only select repositories**，仅选该仓库，授予 **Contents: Read and write**。把令牌粘贴到 ITER。细粒度令牌通常不能自动创建仓库，因此请先建仓库。

仓库设置使用 `owner/name`，新用户留空时为 `<登录名>/iter-sync`。已同步过的旧用户继续使用原仓库，应用不会擅自改名远端仓库。仓库必须私有；有创建权限时，缺失的个人仓库会自动以私有方式创建。令牌经系统安全存储加密后保存；加密不可用时仅留在内存，并显示提示，重启后需要重新登录。退出登录删除本机保存的令牌，不删除文件或远端仓库。

## 同步与冲突

登录或恢复登录后约 1.5 秒同步一次；之后按 `sync.intervalMin` 定期同步，`0` 关闭后续定时同步，也可手动同步。断网、限流或权限错误会停止本次同步，保留登录状态并显示错误。

同步依据上次成功记录按文件进行三方比较，不依赖设备时钟。只修改一端时传到另一端；两端同时修改同一文件时，原路径采用远端版本，本地版本另存为 `<文件名>.conflict-<主机>-<日期>-<随机标识><扩展名>`。冲突副本仅留在本机，不会再次收集、上传或导出。恢复时先比较备份与当前配置，再手动应用所需内容；`settings.json` 作为一个整体处理，不逐字段合并冲突。同步过程中发生的本地保存也会保留备份。

主题和字体的删除仅在另一端未修改时传播；删除与修改并存时保留修改后的文件。设置文件始终由当前设置和默认值生成，远端删除 `settings.json` 后会重新上传本机配置。下载的设置先校验，再替换主进程的实时配置（包括映射键的删除）；本机最近文件与目录保留。界面资源及已激活插件需重新加载或重启后使用新配置。

升级后，旧同步仓库中的题目、代码、测试和代码库文件会被忽略，并从本机同步基线中移除；不会自动清理远端历史或本地数据。如需清理旧备份，请自行处理原仓库，或改用新的私有配置仓库。

UI 可订阅 `sync.onState`：`signing-in` 含验证码、验证地址和到期时间；`syncing` 可含进度；`idle.lastError` 含失败原因或“仅内存保存令牌”的提示。登录/手动同步失败的 Promise 也会拒绝，需捕获。`SyncResult` 与 `SyncState` 的字段和联合类型均未改变。`SyncResult.conflicts` 是发生冲突的原配置相对路径（例如 `settings.json` 或 `themes/custom.json`）；`uploaded` / `downloaded` 包含传播的删除，`skipped` 含相对路径与原因，也会报告远端的非配置文件。`AppSettings` 新增 `pluginEnabled: Record<string, boolean>`，默认 `{}`。
