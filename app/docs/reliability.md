# 数据保存、恢复与隔离验收

题目配置仍使用 `ProblemConfig` v1。设置更新通过显式源码路径和 settings patch 提交，主进程在题目锁内读取最新配置并合并；测试列表由测试接口维护。编辑队列按路径和测试 ID 串行化，运行、调试、打包和退出会等待刷新。删除先封闭编辑入口并等待已开始的写入。保存失败保留编辑内容并允许重试。

## 异常后的恢复

- 源码保存先写入同目录临时文件并同步，再替换目标；写入或替换失败保留原文件。Windows 保存保留 `iter.id` 题目关联，符号链接通过真实目标保存。普通保存按编辑器记录的磁盘正文检查外部变更，暂存完成后再次检查；这不是对其他进程的文件锁，检查与替换之间仍存在很短的并发窗口。自动保存遇到冲突停止，手动保存可明确选择覆盖，确认后仍检查刚才看到的磁盘版本。
- 启动失败或 React 界面异常显示恢复页。启动未完成时不覆盖原会话；正常编辑期间的界面异常先暂停周期保存，最多等待 4 秒保留当前会话，失败时明确显示未保存。渲染进程退出、页面加载失败及启动长时间未完成时，由主进程提供恢复入口。
- 异常恢复的重新启动和退出由用户选择，随后最多等待 8 秒清理后台任务，不依赖已经失效的渲染进程确认。正常关闭仍使用原有保存协商流程。进程已经崩溃时只能恢复最近成功写入的会话。
- `problem.json` 解析失败时，原始字节保存在同目录 `problem.json.corrupt-<SHA256>.json`，当前操作报错并停止自动写入。先保留损坏文件和备份，再用可信配置恢复；不要直接删除整个题目目录。
- 导入以 `.import-<UUID>/journal.json` 记录 prepared/committed 状态，替换 `problem.json` 是提交点。重新加载题目会先恢复事务，再扫描孤立测试文件。提交前回滚新文件，提交后继续清理旧文件和刷新快照；外部链接文件不删除。
- 若日志和当前配置不能确定提交状态，会保留全部数据并报错。此时先复制整个题目目录，包括隐藏事务目录，再人工比较 `before.json`、`after.json` 和当前配置。不要只删除日志来绕过错误。
- 关闭窗口需要渲染进程确认保存完成，随后等待本实例拥有的后台任务和插件窗口清理。取消、保存失败或协商超时都会保留窗口。清理阶段失败后可重试退出。
- Untitled 首次保存迁移身份时，已落盘文本与实时缓冲区分别保存；保存期间的新编辑保留为未保存状态。新旧 model 共用稳定的操作 owner，关闭、重复保存和迁移不会分裂成并行写入队列。启动恢复完成前的外部打开请求排队处理，同一规范路径只对应一个 model。
- 会话保存按文件串行；退出先暂停周期保存，等待已接受的文件操作和旧会话请求，再提交最终快照。超时恢复交互后，新一轮关闭使用独立请求代次。
- 普通测试点编辑和删除使用导入事务的同一恢复机制。修改输入和答案时先保留原件，以带内部事务标记的 `problem.json` 替换为提交点；提交前失败恢复旧输入和答案，提交后继续清理。运行 lease 仍禁止修改正在使用的测试集。
- 本地设置、IPC 更新、配置包和同步共用运行时校验。损坏字段恢复默认值，原始设置文件保留；下一次保存前先建立按 SHA-256 命名的恢复副本。未知字段不会进入有效配置。

这些恢复机制覆盖应用异常退出；不保证突然断电时磁盘或文件系统没有丢失尚未落盘的目录元数据。

## 缓存与调试预算

内置比较与自定义 checker 共用检查方式入口，但分别保留比较规则、文件和参数，切换后可以恢复。运行只读取当前启用的 checker 或交互器，不把未启用工具的目录加入头文件搜索。交互模式保留普通运行的文件 IO 配置但不使用它，也不会自动覆盖它；切回普通运行后恢复。grader 联编配置独立保留。运行或调试占用题目时，界面与存储层均阻止切换执行配置。

编译缓存记录每个翻译单元的真实依赖和编译器内容标识，并在命中前重新计算依赖集合，检查嵌套头文件和搜索路径遮蔽变化。显式链接外部库、对象、响应文件或自定义链接器参数时保守地禁用持久缓存复用。失败、取消和构建期间变动的输入不会发布有效缓存。

编译目录默认最多 2 GiB，7 天未使用的产物可淘汰；构建或运行中的产物受到引用保护。调试默认最多 128 MiB trace、100 万累计节点，输出沿用工具链输出上限；超限停止程序并保留已有记录。输出轮询验证历史内容以检测覆写、截断和回退，采用有界块读取，长输出会增加磁盘读取量。

实时运行中的调试输出按尾部增量读取，每秒至少完整校验一次；暂停、快照及默认精确轮询保留完整校验，不以文件大小或时间戳代替内容检查。独立终端等待 xterm 完成写入的 ACK 才继续消费 helper 输出，慢窗口会将背压传回原生管道；关闭会中断 ACK 等待并结束程序 job，原生退出超时才强制清理。

测试点列表先读取有界并发的元数据，展开时再读取单点预览；未加载或截断的预览不会作为完整数据写回。兼容批量预览接口限制为 8 项并发、总计 400 万字符。界面结果按测试 ID 独立订阅，进度事件按帧合并，并在结束/错误事件前刷新；监视表达式仅在自身变化时写入本地存储。

光标位置独立于全局应用状态，只通知状态栏等光标订阅者。编辑修改标记先比较 Monaco 版本号与正文长度，仅在版本不同且长度相同时读取完整正文，保留撤销和手动恢复原文时的正确标记。

FIM 仅接受用户单次触发（默认 Alt+F）；输入变化不会发起 FIM 请求，每次触发最多调用一次。旧版自动模式及请求延迟设置不再生效；请求期间源代码发生变化时丢弃过期结果。

测试卡片按可见区域挂载，并根据展开内容测量高度；正在使用键盘编辑的卡片在滚动离屏时仍保留。列表保留样例展开、编辑和单项运行，结果概览最多绘制 80 段。测试正文仍通过原有编辑队列保存。

单个输入、答案及输出框最多渲染前 100,000 字符、2,000 行，长行不自动折行；大段粘贴在浏览器插入正文前接管，完整内容仍进入保存队列，界面只呈现只读预览。文件预览的读取上限和最终评测使用的数据保持独立。

会话快照按文档版本复用未变化的正文，同时记录 Monaco 光标、选择、滚动和折叠状态。会话保存失败会在状态栏显示重试入口；损坏的会话文件停止恢复并保留文件，避免按空会话清理临时缓冲区。恢复时优先显示上次活动标签，随后恢复其余标签并还原原顺序；完成前继续保持启动操作队列。

输出差异视图共享内置检查器的词元及数值比较规则，标识多余、缺失和改变的内容，支持首个差异、前后差异和空白显示。自定义检查器只提供辅助文本对比。对比限于预览的前 100,000 字符与 2,000 项，大量差异使用有界局部对齐，界面明确显示限制；最终判定仍来自评测器。

设置、账号、导入弹窗、调试面板和输出对比分别按需加载，Monaco 编辑功能保持完整。在线提交功能及其快捷键、IPC、提交器注册和内置提交插件已移除。内置笔记插件及入口也已移除，通用插件扩展接口继续保留。

## 隔离验收

针对源码保存与异常恢复，可在生产构建后单独运行以下隐藏窗口检查；原生对话框与重新启动动作使用测试替身，所有数据均位于独立的 `app/.cache/audit/recovery-*` 目录：

```powershell
node node_modules/electron/cli.js scripts/verify-recovery.cjs boundary
node node_modules/electron/cli.js scripts/verify-recovery.cjs startup
node node_modules/electron/cli.js scripts/verify-recovery.cjs crash
```

分别验证保存冲突和界面错误后的缓冲区恢复、启动失败时保留原会话，以及真实渲染进程崩溃后的重启请求与退出。2026-10-25 的本机验收被 Electron 分发目录的 AppContainer ACL 阻止，尚未运行成功；相关单元回归、类型检查和生产构建通过。

在 `app` 目录执行：

```powershell
npm run verify:isolated
# 可指定一个不存在、位于源项目外的目录：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-isolated.ps1 -WorkRoot D:\IterVerification\run-001
```

脚本先检查链接和凭据候选，再创建包含依赖和工具链的物理副本，排除 Git 元数据。已有目标不会覆盖。所有检查在副本中运行，临时目录、用户目录、Electron 会话、题目存储和构建结果均指向隔离区域。源目录只被读取。

验收包含 TypeScript、完整 `src` 测试、Electron 构建，以及真实窗口的保存退出、取消退出、保存失败重试和插件窗口清理。窗口测试使用合成代码与测试点，并在启动前设置、启动后核验 Electron 实际用户目录；网络仅使用本地替身。结果和日志保存在新工作区 `test-results`，工作区不会自动删除。真实工具链测试如被跳过，应检查报告中的原因，不能用通过数量代替工具链验证。

回滚源码应使用修复前已验证的完整备份，在应用退出后按需恢复文件；恢复前另存修复后新增工作。无需删除备份、重置 Git 或覆盖现有用户数据。
